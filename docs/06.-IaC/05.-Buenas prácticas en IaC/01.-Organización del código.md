Una buena organización del código en IaC es clave para garantizar la mantenibilidad, escalabilidad y reutilización de las configuraciones de infraestructura. Para lograr esto, es fundamental seguir una estructura modular y utilizar adecuadamente variables y roles.

#### **Estructura Modular**

Dividir la configuración de IaC en módulos bien definidos permite un desarrollo más organizado y facilita la reutilización del código. En herramientas como Ansible, esto implica estructurar los archivos en directorios separados según su funcionalidad, por ejemplo:

```
project/
│── inventories/
│   ├── production
│   ├── staging
│── roles/
│   ├── webserver/
│   │   ├── tasks/
│   │   ├── handlers/
│   │   ├── templates/
│   │   ├── vars/
│── playbooks/
│   ├── site.yml
│── group_vars/
│── host_vars/
```

Este tipo de estructura modular permite la separación clara de responsabilidades y facilita la gestión de entornos con diferentes configuraciones.

#### **Uso de Variables y Roles**

El uso de variables en IaC evita la redundancia y hace que el código sea más flexible y adaptable. En Ansible, las variables pueden definirse a diferentes niveles: en archivos de inventario, dentro de roles o incluso en archivos específicos (`group_vars`, `host_vars`). Por ejemplo:

```yaml
# group_vars/webservers.yml
nginx_port: 80
server_name: example.com
```

Los **roles** permiten encapsular configuraciones específicas dentro de una estructura organizada de tareas, plantillas y variables, facilitando la reutilización y la modularidad. Un rol bien definido en Ansible puede ser utilizado en diferentes proyectos sin necesidad de duplicar código.

Adoptar estas buenas prácticas en la organización del código garantiza una mayor claridad en la administración de la infraestructura y reduce el riesgo de errores en despliegues futuros.
