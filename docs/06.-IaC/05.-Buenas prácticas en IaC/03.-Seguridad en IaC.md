La seguridad en Infraestructura como Código (IaC) es un aspecto fundamental para garantizar la protección de datos sensibles y la consistencia en los despliegues. Una mala gestión de la seguridad puede exponer credenciales, configuraciones críticas o permitir cambios imprevistos en los sistemas. Para mitigar estos riesgos, es clave el uso de herramientas como **Ansible Vault** para manejar datos sensibles y la aplicación de **principios de idempotencia** para garantizar despliegues predecibles y seguros.

#### **Uso de `ansible-vault` para Datos Sensibles**

Ansible Vault es una funcionalidad que permite cifrar archivos o variables sensibles dentro de los playbooks de Ansible, evitando la exposición de credenciales o configuraciones críticas en repositorios de código.

1. **Crear un archivo cifrado**
    Para cifrar un archivo con datos sensibles, se usa el siguiente comando:

   ```sh
   ansible-vault create secrets.yml
   ```

   Esto abrirá un editor donde se pueden agregar credenciales o claves API:

   ```yaml
   db_password: "supersecreto123"
   api_key: "abcdef123456"
   ```

2. **Editar archivos cifrados**
    Si se necesita modificar un archivo protegido, se usa:

   ```sh
   ansible-vault edit secrets.yml
   ```

3. **Ejecutar playbooks con archivos protegidos**
    Para ejecutar un playbook que contiene datos cifrados, es necesario proporcionar la clave de descifrado:

   ```sh
   ansible-playbook site.yml --ask-vault-pass
   ```

4. **Descifrar archivos (si es necesario)**
    Para compartir configuraciones en texto plano temporalmente:

   ```sh
   ansible-vault decrypt secrets.yml
   ```

El uso de `ansible-vault` permite mantener la seguridad de la información sensible y evitar su exposición en repositorios de código público o accesible a usuarios no autorizados.

#### **Principios de Idempotencia**

La idempotencia es un concepto clave en IaC que garantiza que la ejecución repetida de un mismo script de configuración siempre produce el mismo resultado, sin generar cambios innecesarios en los sistemas.

1. **Evitar cambios innecesarios**
    Un buen script de IaC debe verificar el estado actual del sistema antes de aplicar cambios. En Ansible, esto se logra usando módulos que comprueban si una acción ya ha sido aplicada antes de ejecutarla. Por ejemplo, en lugar de forzar la reinstalación de un paquete:

   ```yaml
   - name: Instalar Nginx
     apt:
       name: nginx
       state: present
   ```

   En este caso, si Nginx ya está instalado, Ansible no hará cambios.

2. **Uso de `check_mode` y `--diff`**
    Antes de ejecutar cambios en un sistema, se recomienda probar la configuración en modo de verificación:

   ```sh
   ansible-playbook site.yml --check --diff
   ```

   Esto permite detectar qué cambios se aplicarían sin ejecutarlos realmente.

3. **Evitar comandos imperativos**
    En lugar de ejecutar comandos arbitrarios con `command` o `shell`, es mejor usar módulos específicos que garanticen idempotencia. Por ejemplo, en lugar de:

   ```yaml
   - name: Crear directorio
     command: mkdir /opt/app
   ```

   Se debe usar:

   ```yaml
   - name: Asegurar que el directorio existe
     file:
       path: /opt/app
       state: directory
   ```

Aplicar estos principios de seguridad y idempotencia en IaC permite minimizar errores, proteger la infraestructura y garantizar despliegues predecibles y seguros en cualquier entorno.
