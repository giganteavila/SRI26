### 04.- Playbooks de Ansible

#### Estructura de un playbook

Un playbook en Ansible es un archivo YAML que contiene una o varias tareas a ejecutar en los servidores remotos. Su estructura básica es la siguiente:

```yaml
---
- name: Nombre del playbook
  hosts: all
  become: yes  # Permite ejecutar tareas con privilegios elevados
  tasks:
    - name: Nombre de la tarea
      módulo:
        parámetro: valor
```

#### Creación de tareas (tasks)

Las tareas en un playbook definen las acciones a ejecutar en los nodos remotos. Cada tarea especifica un módulo y sus argumentos. Ejemplo:

```yaml
- name: Crear un archivo de prueba
  copy:
    dest: /tmp/prueba.txt
    content: "Este es un archivo de prueba"
```

#### Uso de módulos populares

Algunos de los módulos más utilizados en Ansible incluyen:

- **`apt`** (para sistemas basados en Debian):

  ```yaml
  - name: Instalar Nginx en Debian/Ubuntu
    apt:
      name: nginx
      state: present
  ```

- **`yum`** (para sistemas basados en RHEL/CentOS):

  ```yaml
  - name: Instalar Nginx en CentOS/RHEL
    yum:
      name: nginx
      state: present
  ```

- **`copy`** (para copiar archivos):

  ```yaml
  - name: Copiar un archivo
    copy:
      src: archivo_local.txt
      dest: /tmp/archivo_remoto.txt
  ```

- **`template`** (para manejar archivos con variables):

  ```yaml
  - name: Copiar una plantilla de configuración
    template:
      src: plantilla.conf.j2
      dest: /etc/software.conf
  ```

- **`service`** (para gestionar servicios):

  ```yaml
  - name: Reiniciar Nginx
    service:
      name: nginx
      state: restarted
  ```

#### Variables y facts

Las variables en Ansible permiten personalizar las configuraciones. Se pueden definir en el playbook o en archivos separados:

```yaml
- name: Instalar un paquete con variable
  apt:
    name: "{{ paquete }}"
    state: present
```

Los facts son información recolectada automáticamente sobre los sistemas remotos y pueden utilizarse dentro del playbook:

```yaml
- name: Mostrar la dirección IP del sistema
  debug:
    msg: "La IP del servidor es {{ ansible_default_ipv4.address }}"
```

Con estos elementos, los playbooks en Ansible permiten automatizar y gestionar configuraciones de forma flexible y eficiente.
