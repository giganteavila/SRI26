## Uso de Ansible como herramienta de provisionamiento en Vagrant

**Vagrant** y **Ansible** son herramientas complementarias que facilitan la automatización de entornos de desarrollo y producción. Mientras que **Vagrant** gestiona la creación y configuración de máquinas virtuales, **Ansible** se encarga de su aprovisionamiento, instalando software, configurando servicios y asegurando la coherencia del entorno.

La integración entre **Vagrant y Ansible** permite definir un entorno de infraestructura como código (IaC) completamente automatizado, eliminando la necesidad de configuraciones manuales.

## Métodos de uso de Ansible con Vagrant

Existen dos maneras principales de utilizar **Ansible** dentro de un entorno Vagrant:

1. **Modo local (`ansible_local`)**: Ansible se ejecuta dentro de la máquina virtual de Vagrant.
2. **Modo remoto (`ansible`)**: Ansible se ejecuta desde el sistema anfitrión (host) y gestiona la VM de Vagrant.

Cada método tiene ventajas y desventajas según el caso de uso.


### **1. Provisionamiento con `ansible_local` (ejecución dentro de la VM)**

Este método es útil cuando se trabaja en entornos donde Ansible no está instalado en el sistema anfitrión. Vagrant se encarga de instalar Ansible en la VM antes de ejecutar el aprovisionamiento.

#### **Ejemplo de configuración en el `Vagrantfile`**

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/bionic64"

  # Provisionamiento con Ansible dentro de la VM
  config.vm.provision "ansible_local" do |ansible|
    ansible.playbook = "provision.yml"
  end
end
```

En este caso, Vagrant ejecutará Ansible dentro de la máquina virtual y aplicará el playbook **`provision.yml`**.

#### **Ejemplo de Playbook `provision.yml`**

```yaml
- hosts: all
  become: yes
  tasks:
    - name: Actualizar lista de paquetes
      apt:
        update_cache: yes

    - name: Instalar Apache
      apt:
        name: apache2
        state: present

    - name: Iniciar y habilitar Apache
      service:
        name: apache2
        state: started
        enabled: yes
```

Este playbook instala **Apache** en la máquina virtual, asegurándose de que el servicio esté habilitado y en ejecución.

**Ventajas de `ansible_local`:**

- No requiere Ansible en el host.
- Es fácil de configurar.

**Desventajas de `ansible_local`:**

- Puede ser más lento, ya que Ansible debe instalarse en la VM.
- No permite administrar múltiples máquinas desde el host.



### **2. Provisionamiento con `ansible` (ejecución en el host)**

En este caso, **Ansible** se ejecuta desde el sistema anfitrión y gestiona la máquina virtual de Vagrant de forma remota. Esto es más eficiente y permite la gestión de múltiples máquinas desde un solo punto.

#### **Ejemplo de configuración en el `Vagrantfile`**

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/bionic64"

  # Configurar red para que Ansible pueda conectarse a la VM
  config.vm.network "private_network", type: "dhcp"

  # Configurar Ansible como provisionador en el host
  config.vm.provision "ansible" do |ansible|
    ansible.playbook = "provision.yml"
    ansible.inventory_path = "inventario"
  end
end
```

#### **Archivo de inventario (`inventario`)**

```ini
[vagrant]
192.168.56.10 ansible_ssh_user=vagrant ansible_ssh_private_key_file=.vagrant/machines/default/virtualbox/private_key
```

#### **Ejemplo de Playbook `provision.yml`**

```yaml
- hosts: vagrant
  become: yes
  tasks:
    - name: Instalar paquetes básicos
      apt:
        name: ["git", "curl", "htop"]
        state: present
```

En este caso:

- Se configura una **red privada** para que Ansible pueda acceder a la máquina virtual.
- Se define un **inventario** con la dirección IP de la VM.
- Ansible se ejecuta desde el **host**, lo que mejora el rendimiento.

**Ventajas de `ansible`:**

- Permite administrar varias VMs desde el host.
- Más eficiente que `ansible_local`, ya que no requiere instalar Ansible dentro de cada VM.

**Desventajas de `ansible`:**

- Requiere que Ansible esté instalado en el host.
- Necesita configuración adicional para definir la conexión a la VM.

## **Ejemplo de flujo de trabajo con Vagrant y Ansible**

1. **Inicializar un directorio de trabajo**:

   ```bash
   mkdir vagrant_ansible && cd vagrant_ansible
   ```

2. **Crear un `Vagrantfile`**:

   ```bash
   vagrant init ubuntu/bionic64
   ```

3. **Editar el `Vagrantfile` para agregar Ansible como provisionador**.

4. **Escribir el playbook `provision.yml`** con las configuraciones deseadas.

5. **Levantar la VM y ejecutar Ansible**:

   ```bash
   vagrant up
   ```

Si se desea reprovisionar la máquina sin reiniciarla, se usa:

```bash
vagrant provision
```

## Conclusión

La integración de **Vagrant y Ansible** permite la automatización completa de entornos de desarrollo y pruebas. Dependiendo de las necesidades del proyecto, se puede optar por `ansible_local` (ejecutado en la VM) o `ansible` (ejecutado en el host). Este enfoque no solo simplifica la configuración de máquinas virtuales, sino que también garantiza entornos consistentes y reproducibles.
